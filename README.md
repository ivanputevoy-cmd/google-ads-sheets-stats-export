# Google Ads → Google Sheets: экспорт статистики

Скрипт **Google Ads Scripts**, который по расписанию (по умолчанию раз в час) автоматически
выгружает статистику рекламного аккаунта в Google Таблицы — иерархически
(кампания → группа → объявление/ключ), с накоплением истории и удобным оформлением для команды.

Работает в облаке Google: компьютер держать включённым не нужно, внешний сервер и Google Ads
API (developer token) не требуются.

## Возможности

- **Иерархия:** кампания → группы объявлений → объявления (и отдельный лист с ключевыми словами).
- **Накопление истории:** каждый скан дописывается новым блоком, старое не стирается.
- **Метрики за всё время:** в строке — накопленный итог на момент скана.
- **Автоподхват:** новые кампании/группы/объявления/ключи попадают в выгрузку без правок скрипта.
- **Файл на период:** каждый месяц — отдельная таблица, ссылки собираются в реестр (место не кончается).
- **Лист «Сводка»:** итоги по аккаунту и топ кампаний, открывается первым.
- **Оформление:** человекочитаемые числа, заморозка шапки, цвет строк по уровню, подсветка ROAS/конверсий.
- **Время по Москве** в метке каждого скана.
- **Общий доступ:** созданные файлы сразу открыты на редактирование по ссылке (настраивается).
- **Airtable (необязательно):** актуальная сводка (итог + все активные кампании) уходит в Airtable
  для CRM команды — обновлением записей, без дублей.

## Как устроено хранение

Чтобы накопленная история не сваливалась в один бесконечный лист, **каждый период
(по умолчанию — месяц) пишется в отдельную таблицу-файл**:

- **Стартовая таблица — это реестр.** В ней появляется лист **«Файлы»** со списком всех
  созданных таблиц: период, кликабельная ссылка «открыть», ID, дата создания.
- Когда наступает новый месяц, скрипт **сам создаёт новую таблицу** («Google Ads — 06.2026»)
  с нужными листами и дописывает ссылку на неё в реестр.
- Данные пишутся в таблицу текущего месяца.

> Лимит Google — не на число листов, а на объём всей книги (~10 млн ячеек). Поэтому отдельные
> файлы на период — единственный способ хранить историю «вечно» без удаления.

## Что внутри каждого файла

Три листа:

- **«Сводка»** — открывается первой. Когда обновлено, итоги по аккаунту за всё время
  (показы, клики, CTR, расход, конверсии, CPA, ценность, ROAS) и топ кампаний по расходу.
  Перезаписывается каждый скан — всегда актуальна.
- **«Статистика»** — дерево: Кампания → её Группы объявлений → их Объявления.
- **«Ключевые слова»** — то же дерево, но в самом низу ключи: Кампания → Группа → Ключ.

Внутри одного скана строки идут деревом:

```
Кампания 1
   ↳ Группа объявлений 1
      ↳ Объявление #123 (RESPONSIVE_SEARCH_AD)
      ↳ Объявление #124 (RESPONSIVE_SEARCH_AD)
   ↳ Группа объявлений 2
      ↳ Объявление #200 (...)
Кампания 2
   ↳ ...
```

Колонки (одинаковые на «Статистике» и «Ключевых словах»):

| Время скана | Уровень | Название | Статус | Показы | Клики | CTR % | Ср. CPC | Расход | Конверсии | CR % | CPA | Ценность конв. | ROAS |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|

- **Время скана** — `дд.мм.гггг чч:мм`, всегда по Москве.
- **Уровень** — `Кампания`, `Группа`, `Объявление` или `Ключ` (удобно фильтровать).
- **Название** — с отступом по уровню.
- Валюта в денежных столбцах подставляется из аккаунта.

**Оформление:** деньги с разделителями тысяч, проценты со знаком, заморожены шапка и первые три
столбца; строки окрашены по уровню (кампания выделена и жирная); ROAS подсвечен (зелёный выше 2,
жёлтый около 1, красный ниже 1), конверсии — зелёные при наличии и серые при нуле.

> При суммировании считай сумму **в пределах одного уровня** (фильтр по «Уровню»). Если сложить
> все уровни сразу, расход посчитается несколько раз — это одни деньги на разной детализации.

## Установка

1. Открой кабинет Google Ads (тот же аккаунт, где реклама).
2. **Создай пустую Google-таблицу** — она будет реестром. Скопируй её ID из ссылки
   (часть между `/d/` и `/edit`).
3. В файле `google_ads_to_sheets.js` впиши этот ID в настройку `REGISTRY_ID`
   (вместо `PASTE_YOUR_SPREADSHEET_ID_HERE`).
4. В кабинете: **Инструменты и настройки** → «Массовые действия» → **Скрипты** → **+**.
5. Удали текст в окне кода, вставь полностью содержимое `google_ads_to_sheets.js`.
6. Нажми **Авторизовать** → выбери Google-аккаунт → **Разрешить** (Google попросит доступ к
   Таблицам и Диску — нужно, чтобы создавать файлы, писать в них и открывать доступ по ссылке).
7. Нажми **Просмотр** (Preview). Проверь:
   - в реестре появился лист «Файлы» со строкой текущего месяца и ссылкой «открыть»;
   - по ссылке — таблица, где первой открывается «Сводка», рядом раскрашенные «Статистика»
     и «Ключевые слова».
8. Сохрани скрипт.

## Расписание

1. В списке скриптов нажми на «Частоту» (иконку расписания) у своего скрипта.
2. Выбери **Ежечасно** (Hourly) → сохрани.

При ежечасном расписании данные обновляются **раз в час**, и каждый запуск результативен.
Частоту записи задаёт настройка `EVERY_N_HOURS` — она должна совпадать с расписанием:
для «Ежечасно» это `1`.

> В Google Ads **нет** расписания «раз в N часов» — только Ежечасно, Ежедневно, Еженедельно,
> Ежемесячно. Поэтому, если нужно реже, чем раз в час, выбирай **Ежедневно** (и поставь
> `EVERY_N_HOURS` равным, например, `24`). Ставить `EVERY_N_HOURS` больше 1 при ежечасном
> расписании не нужно — иначе часть запусков будет холостой.

## Настройки

Все настройки — в начале файла, блок «Настройки».

| Параметр | Назначение |
|---|---|
| `REGISTRY_ID` | ID Google-таблицы-реестра. **Обязательно вписать свой.** |
| `PERIOD` | Дробление файлов: `'month'` (на месяц) или `'year'` (на год). |
| `FILE_PREFIX` | Начало имени создаваемых файлов («Google Ads — »). |
| `DRIVE_FOLDER_ID` | ID папки Google Диска для файлов. Пусто = корень Диска. |
| `SHARE_PUBLIC_EDIT` | `true` = новые файлы сразу открыты на редактирование всем по ссылке. |
| `TOP_N` | Сколько кампаний показывать в «Сводке» (по умолчанию 10). |
| `EVERY_N_HOURS` | Минимальный интервал записи в часах. Должен совпадать с расписанием: «Ежечасно» = `1`, «Ежедневно» = `24`. |
| `TIMEZONE` | Часовой пояс метки времени (по умолчанию `Europe/Moscow`). |
| `STATUS_RU`, `MATCH_RU` | Подписи статусов и типов соответствия ключей. |
| `IND_GROUP`, `IND_LEAF` | Символы отступа дерева. |
| `LEVEL_BG`, `C_GOOD`/`C_MID`/`C_BAD`/`C_ZERO` | Цвета заливки строк и подсветки. |
| `AIRTABLE_TOKEN` | Personal Access Token Airtable. Плейсхолдер = отправка выключена. |
| `AIRTABLE_BASE_ID` | ID базы Airtable (начинается с `app...`). |
| `AIRTABLE_TABLE` | Название таблицы в Airtable. |

Пороги подсветки ROAS (1 и 2) задаются в функции `applyDetailFormat`.

**Набор метрик** меняется в трёх местах согласованно: `metricFields` (что запросить),
`metricRow` (как посчитать и в каком порядке), `buildHeader` (подписи столбцов).

**Только активные** вместо «всё кроме удалённого» — в запросах `fetchTree` замени
`!= "REMOVED"` на `= "ENABLED"`.

## Интеграция с Airtable (необязательно)

Если заданы `AIRTABLE_TOKEN` и `AIRTABLE_BASE_ID`, то на каждом скане скрипт отправляет в
Airtable **актуальную сводку** для CRM команды: одну запись с итогом по аккаунту и по записи
на каждую активную кампанию. Данные **обновляются** (upsert по полю `ID`), а не дублируются —
в Airtable всегда свежее состояние. История при этом остаётся в Google Sheets.

Кампании, пропавшие из выгрузки (приостановлены/удалены), не стираются, а помечаются статусом
**«Неактивна»**.

### Что нужно подготовить

1. **Создай базу и таблицу** в Airtable. В таблице создай поля (названия — точно как ниже):

   | Поле | Тип в Airtable |
   |---|---|
   | `ID` | Single line text (ключ для обновления — у кампании это её ID, у итога — `ACCOUNT`) |
   | `Уровень` | Single select (`Итого`, `Кампания`) |
   | `Кампания` | Single line text |
   | `Статус` | Single select (`Активна`, `Пауза`, `Неактивна`) |
   | `Показы`, `Клики`, `Конверсии` | Number |
   | `CTR %`, `CR %`, `ROAS` | Number |
   | `Ср. CPC`, `Расход`, `CPA`, `Ценность` | Currency (или Number) |
   | `Обновлено` | Date (с включённым временем) |

   > Поля с типом Single select можно оставить пустыми — при первой отправке варианты создадутся
   > автоматически (используется `typecast`).

2. **Узнай Base ID:** открой [airtable.com/api](https://airtable.com/api), выбери базу — ID
   (начинается с `app...`) показан в документации базы. Или возьми из URL базы.
3. **Создай Personal Access Token:** [airtable.com/create/tokens](https://airtable.com/create/tokens) →
   scope `data.records:write` (и `data.records:read` для пометки неактивных) → доступ к нужной базе.
4. Впиши `AIRTABLE_TOKEN`, `AIRTABLE_BASE_ID`, `AIRTABLE_TABLE` в настройки скрипта.

> Токен — секрет. Не коммить его в репозиторий: в коде для git он должен оставаться плейсхолдером,
> реальный токен живёт только в копии скрипта внутри кабинета Google Ads.

### UX в Airtable (рекомендации)

- **Grid-вид** с сортировкой по `Расход` и фильтром по `Статус`; `Уровень = Итого` можно вынести
  отдельным видом или закрепить сверху.
- **Color records** по условию: `ROAS > 2` — зелёный, `1–2` — жёлтый, `< 1` — красный.
- **Currency / %** — задаются типом поля, отображение человекочитаемое.
- **Interface (дашборд)** — собери витрину: крупные числа из строки `Итого`, список топ кампаний,
  поле `Обновлено` как индикатор свежести. Команда заходит в Interface как на дашборд.

## Как работает скрипт

1. **Определяет период** (текущий месяц по Москве) и открывает реестр.
2. **Находит или создаёт файл периода** — новый месяц = новая таблица + ссылка в реестр.
3. **Проверяет интервал** по времени последней записи на листе «Статистика»: если с неё прошло
   меньше `EVERY_N_HOURS` часов — выходит (защита от дублей). При ежечасном расписании пишет каждый запуск.
4. **Запрашивает у Google Ads** кампании, группы, объявления и ключи (период не задан = за всё время).
5. **Строит дерево** и считает производные метрики (CTR, CR, CPA, ROAS), деньги переводит из микро-единиц.
6. **Дописывает строки** на детальные листы и красит их по уровню.
7. **Перерисовывает «Сводку»** и ставит её первым листом.
8. **Отправляет сводку в Airtable** (если настроено) — итог и активные кампании, обновлением записей.

## Замечания и ограничения

- Данные за сегодняшний день Google Ads обновляет с задержкой ~1–3 часа — это норма.
- Удалённые сущности в выгрузку не попадают.
- Файлы создаются от лица того Google-аккаунта, под которым авторизован скрипт.
- Если аккаунт корпоративный (Google Workspace) и админ запрещает внешний доступ — файл создастся,
  но останется приватным; в журнале будет строка «Не удалось открыть доступ…».
- **Управляющий аккаунт (MCC):** скрипт собирает данные одного аккаунта. Для обхода всех
  под-аккаунтов нужна доработка через `MccApp`.
- **Performance Max:** у таких кампаний нет обычных групп и ключей, в дерево они не попадут.
